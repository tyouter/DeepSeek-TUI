# 需求池

> 最后更新：2026-05-10 | Pipeline v1.0

## 图例

- **优先级**: P0 (阻塞) / P1 (高频痛点) / P2 (值得做) / P3 (锦上添花)
- **生命周期**: 🔴 待评审 / 🟡 已评审/就绪 / 🟢 开发中 / 🔵 已提交 PR / ✅ 已合入 / ❌ 不做 / ⏸️ 阻塞
- **工作量**: S (小时级) / M (天级) / L (周级)
- **类型**: [FEAT] 新功能 / [FIX] 修复 / [PIPELINE] 流程改进 / [REFACTOR] 重构
- **来源**: 使用中发现 / 上游 Issue / 社区反馈

## 条目格式

每个需求条目包含以下字段：

```markdown
### <REQ-ID>: <类型> <标题>

- **优先级**: P0/P1/P2/P3
- **生命周期**: 🔴/🟡/🟢/🔵/✅/❌/⏸️
- **工作量**: S/M/L
- **来源**: 
- **涉及 crate**: 
- **风险**: 
- **分支**: feat/<REQ-ID>-<slug>
- **PR**: 链接（合入后填写）
- **验收标准**:
  - [ ] 标准 1
  - [ ] 标准 2
- **备注**: 
```

## 详细规格

复杂需求的详细设计文档放在 `specs/` 目录下，以需求 ID 命名。

已生成的 PR 文档：
- `specs/<REQ-ID>-pr-body.md` — PR 描述正文
- `specs/<REQ-ID>-changelog.md` — changelog 条目
