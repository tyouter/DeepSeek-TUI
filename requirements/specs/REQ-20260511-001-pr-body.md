## What

Fix three rendering defects in the Ctrl+R session resume picker:
1. Session titles showing `<turn_meta>` instead of the user's actual prompt
2. Preview panel leaking system prefix (`<turn_meta>`) into the first user message
3. Earlier conversation messages appearing empty when they contain Thinking blocks

## Why

When DeepSeek TUI saves a session, the first user message text contains a `<turn_meta>...</turn_meta>` block injected by the system. The title extraction logic used this raw text directly, resulting in every session title showing `<turn_meta>`. The preview panel had the same issue — concatenating raw text blocks without stripping system prefixes. Additionally, assistant messages containing `ContentBlock::Thinking` (reasoning tokens) were silently ignored, producing empty `ASSISTANT:` lines in the preview.

## How

### `session_manager.rs`

- Added `extract_user_prompt(raw: &str) -> &str` — strips a leading `<turn_meta>...</turn_meta>` block from message text. Returns the trimmed original if no such block is present.
- Updated `create_saved_session_with_mode` to pass first user message text through `extract_user_prompt` before generating the session title.

### `session_picker.rs` — `build_preview_lines`

- Apply `extract_user_prompt` to **all** user messages in the preview (not just the first)
- Skip `ContentBlock::Thinking` blocks entirely — only show the final Text response for assistant messages
- Skip messages that have no visible text after cleaning (no more empty `USER:` or `ASSISTANT:` lines)

### Tests

- 7 unit tests for `extract_user_prompt` covering: normal text, turn_meta prefix, leading whitespace, turn_meta-only input, mid-text turn_meta (should not strip), empty strings, whitespace-only
- 5 unit tests for `build_preview_lines` covering: normal dialogue display, turn_meta stripping, thinking block skipping, empty message skipping, thinking-only assistant message handling
