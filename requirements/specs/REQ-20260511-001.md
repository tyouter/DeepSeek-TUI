# REQ-20260511-001: Ctrl+R 会话恢复界面渲染缺陷

## 目标

修复 Ctrl+R 会话列表中的三个显示缺陷：Title 显示 `<turn_meta>`、首条消息预览泄露系统前缀、早期对话消息显示不全。

## 根因分析

### Bug 1: Title = `<turn_meta>`

`session_manager.rs:create_saved_session_with_mode` 取第一条 `role=="user"` 消息的第一个 `ContentBlock::Text` 作为 title。但系统在用户消息前注入了 `<turn_meta>` 块，导致 `text` 字段以 `<turn_meta>` 开头，`truncate_title` 截取的就是系统元数据而非用户实际 prompt。

### Bug 2: 预览首条消息含系统前缀

`session_picker.rs:build_preview_lines` 遍历前 6 条消息，拼接所有 `ContentBlock::Text` 的 `text` 字段。第一条 USER 消息的 text 同样含 `<turn_meta>` 前缀，直接展示给用户。

### Bug 3: 早期消息显示不全 / 空条目

`build_preview_lines` 只取前 6 条消息，且只处理 `ContentBlock::Text`。如果早期消息含 `ContentBlock::Thinking` 块（推理 token），文本累积为空字符串，渲染为 `USER:` 或 `ASSISTANT:` 空行。另外取"前 6 条"可能全是系统/元数据消息，用户真正关心的对话反而没显示。

## 验收标准

- [ ] 会话列表的 Title 列显示用户首条 prompt 的摘要（排除 `<turn_meta>` 等系统标签）
- [ ] 预览面板的首条 USER 消息展示纯用户 prompt（排除系统前缀和 turn_meta 块）
- [ ] 历史对话中 USER/ASSISTANT 消息均完整显示（Thinking 块显示占位符，不出现空条目）
